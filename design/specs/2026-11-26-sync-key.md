# Sync key: `S` syncs without quitting

Date: 2026-11-26. Status: **built** the same day. Andreas's idea.

## The problem

The TUI syncs at the edges: pull on start, commit and push on quit. A
corkboard is meant to stay open, so a pin marked with `P` (or any other
change) does not reach the other machine, or syncz reading the board's
remote, until pinz quits. The only way to sync mid-session is to quit or to
run `pinz sync` in another terminal.

## The design

**`S` in the board runs the same steps as `pinz sync`: save, commit, pull,
push, then re-read the board from disk.**

- Shift+S, not `r`: it commits and pushes, and the README's rule is that
  anything that moves commits is not a casual keystroke. Named Sync, not
  Refresh, because refresh reads as pull-only (the same trap `up` fell into).
- The app only queues the request (`take_pending_sync`), like a copy or a
  world delete; the runner does the git work, so the app stays testable with
  no repo.
- Order: save the board, commit, pull, push. A pull that brought commits in
  re-reads the board, keeping the open world (by name), the camera and the
  selection when that pin still exists. Undo history is cleared: undoing
  across a pull would write the other machine's changes away.
- The footer says what happened in one line: `synced: in sync`,
  `synced: pulled 2 commit(s), pushed to pinz-board`, and so on.
- A stopped pull or push becomes the sticky warning, the same as a stopped
  pull at startup, and the quit skips its push. A later `S` that gets through
  clears that warning and lets the quit push again.
- A read-only session refuses `S` like any other change. With `--no-sync` the
  footer says sync is off this run.
- The terminal is drawn with `syncing...` before the git work starts, since a
  fetch over a slow network blocks for a moment.

In a note, `S` is a capital S: the key only means sync on the board.

## The flashes

- A sync that got through plays a wave: a crest about ten columns wide
  crosses the board left to right in 0.5 s, lighting the text under it
  toward the theme's accent. Blank space stays still. A stopped sync plays
  nothing; its warning is the news.
- Copying is a chord, as in notez and fleetz: `yy` copies the pin whole and
  `yp` is kept for copying its path, which needs the store to report a pin's
  file and is not built yet (it says so in the footer). A lone `y` shows the
  two choices; any other key, or a click, drops the chord.
- `yy` flashes the copied pin the way notez and fleetz flash a yanked row: its
  background brightens behind a front sweeping left to right (0.1 s), then
  fades back (0.2 s). `yp` will sweep from the right. The footer's
  `copied N chars` is unchanged.
- Both run on the camera glide's frame loop (`App::animating`, `App::tick`),
  so pinz is back to blocking for input, at zero CPU, once they end. Neither
  changes board data, so neither causes a save.
